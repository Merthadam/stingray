## Lifecycle correctness gaps

### Codex

Saved reference: `artifacts/testing/agent-status/reference/codex-hooks.md`.

- Lines 1091–1123: Stop handlers can request another turn through `decision: "block"` or exit code 2. Other handlers run concurrently. Observing our own Stop invocation therefore cannot prove that all handlers allowed settlement. `stop_hook_active` describes earlier continuation, not the outcome of the current handlers.
- Lines 840–898: PermissionRequest occurs before the normal approval decision. Another hook can allow or deny it, avoiding any user prompt. Treating it as confirmed "Waiting for you" is not exact.
- PermissionRequest lacks the `tool_use_id` supplied on PostToolUse, so parallel permission resolution cannot safely be paired merely by tool name. A later unrelated tool completion must not clear all pending requests.
- Lines 967–981: PostModelRequest describes a model-request attempt, not final agent settlement.
- The installed generated `HookEventName` schema has no post-settlement event. This is a limitation of the inspected hook interface, not proof that every Codex integration API is incapable of supplying the needed signal.

A timeout, quiet terminal, sleeping process, or an acknowledgement click is not a substitute for missing lifecycle evidence. Returning `continue: false` to force a final Stop would alter agent behavior and is prohibited.

### Claude Code

At the earlier capability probe, `claude` was absent from PATH. This is not a fresh availability check. No Claude installation or CLI launch is part of the Pi-only verification.

Saved reference: `artifacts/testing/agent-status/reference/claude-hooks.md`.

- Lines 2787–2890: Stop hooks can continue execution; background tasks and scheduled wakeups are separate concerns. An individual Stop handler cannot certify the aggregate decision.
- Lines 2120–2137: PermissionRequest occurs before the actual prompt/auto-denial and has no tool-use ID. Not every network permission prompt fires this event.
- Lines 2508–2553: idle/permission notifications have conditional delays and availability. They are not a universal immediate four-state signal.

Per-session plugin attachment and runtime composition remain unverified. Fixtures alone cannot establish installed-Claude compatibility or complete permission/settlement coverage.

### Pi — implemented, version-gated

The inspected Pi 1.5.0 extension API provides:

- `agent_settled` after retries, compaction, queued continuations and stop-boundary decisions; `agent_end` is not final.
- `ui_prompt_start/end` for a coalesced blocking extension-UI span.
- `session_start/shutdown` for runtime replacement and exit, which must not be confused with task completion.

`agents/pi-extension.ts` loads the host VERSION; `agents/pi-observer.ts` accepts exactly **1.5.0**. It observes scalar lifecycle fields without reading prompts, messages, tool data, UI titles or session files and returns no hook decisions. Successful settlement increments a completion counter; error/abort/unknown outcomes do not. Synthetic tests cover continuation/retry boundaries, failure, interruption and conservative unknown states. Real no-provider smoke proves bundled-extension loading, confirmation UI start/end, `/reload`, `/new`, and shutdown.

`electron/activity-shell.ts` attaches through a temporary zsh startup/PATH wrapper in new terminals, adding the bundled extension without writing global configuration. Existing arguments/extensions, aliases/functions and user startup ordering are preserved in fixture coverage. Other shells, explicit executable paths, later PATH overrides, nested-shell startup choices, disabled extensions, maintenance/help and noninteractive invocations may bypass tracking. No shell or process liveness is relabeled as agent idle.

The private socket in `electron/activity.ts` uses strict schemas, terminal-bound capabilities, monotonic sequence/completion metadata and absolute valid-frame lease deadlines. Renderer snapshots contain only opaque IDs, connection, phase and review revision, never the capability. Limits: 8 retained runs per terminal, 64 sockets, 64 retired runtimes per run; 1 KiB frames, 8 KiB receive buffer, 100 frames/second/socket, 2-second authentication deadline and 20-second lease. Directory/socket modes are 0700/0600. This is **not hostile same-user isolation**. Activity is memory-only and does not survive app exit.

## Current scope and remaining capability gates

The selected scope is Pi-only source integration, with Claude/Codex tracking unsupported. The earlier all-three proposal remains historical research, not a gate that was silently passed. No approximation of missing Claude/Codex lifecycle events was implemented.

Remaining limits:

- Only Pi 1.5.0 on the tested macOS/new-zsh-terminal path is verified. Unsupported versions report unavailable if the extension can load; a load/API failure may leave the invocation unattached.
- Waiting covers **blocking extension UI**, not all built-in pickers, notifications or permission mechanisms.
- Cancellable compaction/tree boundaries may remain unknown without a resolving event. No fabricated completion or idle is used to clear them.
- Real-provider turns, retries, tool outcomes, resume/fork flows and arbitrary user extension/configuration combinations have not been runtime-verified. Synthetic tests are not provider evidence.
- Exact-revision acknowledgement has view/focus, rendered-bottom and pending-write guards, with native tests for hidden panes, scrollback, split panes, reload and late completions. This is bounded coverage, not an exhaustive proof of render/event ordering.
- Reconnection/reload preserves unseen completion; a disconnect does not imply successful completion. Closing a terminal revokes/removes its activity. Capacity limits can refuse additional tracking rather than evict unseen review.
- A separate candidate is now packaged and verified; actual installed-app promotion remains a separate reported gate. Broader adapters, unrelated production fixes and real-provider verification are not part of this delivery.

Never force settlement, bypass permissions/trust, install global hooks, scrape transcripts, or manufacture idle from silence to get past these gates.
